对三个已有来源应用自动和 20 条本机自定义排除规则。评测快照的索引记录从 32,991 条降至 11,422 条，保留 1,097 份已有正文的微信附件。重处理 785 条 Office 记录，结合排除规则，文本块从 525,848 降至 196,174，不足 30 字的块从 72,989 降至 11,662。评测快照的 160,635 个正文块均有当前 BGE 向量。压缩包与 EXE 元数据可用关键词检索。

混合检索的实盘 Hit@5 从 33/36 升至 34/36，最终复测在后台扫描运行时的 p95 为 2.91 秒，基线为 26.63 秒。预计无答案的 6 条中仍有 5 条返回结果。关键词、语义与混合的详细测量见 [检索评测](evaluation.md)。

Ruff 检查与格式检查、锁文件校验和源码包及 wheel 构建通过。pytest 复跑 29 项通过，真实模型用例因未设置 `FILEMIND_TEST_MODEL` 跳过。

本机原生窗口验证了混合检索、按行范围预览、离线问答摘录和排除目录对话框。设置页显示迁移后的数据路径与 DirectML 推理设备。

## 0.1.0.dev3 · 2026-11-13

完成 P0-06 常驻资料库。文档、下载和 D 盘先登记文件名与路径，正文与向量在后台补建。可以按来源或格式筛选，并在资源管理器定位文件。Windows 托盘实测关闭窗口后新建 TXT 仍会自动索引，退出后释放资料库锁。

本机默认资料库已登记三个来源并启用 Windows 登录启动。D 盘首轮名称扫描登记了超过 3.2 万个文件。按扩展名实测查到 Office、PDF、MD、TXT、ZIP、7Z、RAR 和 EXE。正文首轮仍在后台处理。启动命令已写入当前用户的登录启动项并从同一入口启动验证，尚未重新登录 Windows。

23 项 pytest 测试通过，包含真实 BGE 模型、2 万项以上的目录、NTFS 硬链接、Excel 行号、中文 ZIP 条目、EXE 版本信息及文件变更监听。另用 Windows 生成的 `.doc` 和 `.ppt` 样例验证了旧版正文解析，实测了 RAR、7Z 条目读取、原生窗口交互和托盘后台索引。Ruff、锁文件和源码包及 wheel 构建均通过。

首轮实盘索引发现部分 PDF 字体输出了未配对的 Unicode 代理码位。修复后两份受影响的 PDF 均成功索引，待处理队列恢复推进。RTX 4080 Laptop GPU 使用 DirectML 推理 384 个实际文本块耗时 0.92 秒（批次 32），同一批文本在 CPU 上耗时 13.47 秒（批次 16）。两组归一化向量的最小余弦相似度为 0.99999988。这组耗时仅计模型推理。24 项 pytest 测试通过，另外验证了强制 CPU 模式和托盘进程使用 DirectML 补建向量。

修复了 Windows 隐藏启动时首次唤起窗口仍不可见的问题。新增原生 Windows 回归测试，通过托盘激活路径检查窗口的 Win32 可见状态。默认资料库的托盘实例也已通过普通启动入口唤起，并确认主窗口可见。

向量补建独立于目录扫描，GPU 保持每批最多 32 个文本块，每次数据库提交合并最多 128 个。同一批 2,304 个实盘文本块的独立入库测试从 335 个/秒提高到 428 个/秒。托盘实例两段实盘采样的入库速度分别约为 430 和 245 个/秒，调整前约为 80–85 个/秒。RTX 4080 Laptop GPU 整卡每 0.5 秒采样，两段分别平均占用 77% 和 45%，最高 93%。26 项 pytest 测试通过，含真实 BGE 检索及扫描期间提交向量的回归测试。Ruff、锁文件和构建检查均通过。

2026-11-13 18:38，本机资料库的 484,370 个已提取正文块均有当前 BGE 向量，待生成数为 0。桌面端以 `FIRST/FOLLOW` 命中两份 Markdown 正文，可按行号预览。用自然语言查询抽象语法树和语法错误，纯语义模式返回相关 Word 和 PDF，分别核对了段落与物理页预览。一次全库语义查询实测约 17 秒。另有 744 份 PDF 标记为需要 OCR，160 份文件解析失败。
